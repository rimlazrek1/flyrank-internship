Ranking pages with weak CTR for their Google position

Which pages look weak on clicks for their Google rank, and which ones should a reviewer open first? This page compares a simple ctr_gap rule with a logistic model on anonymized March 2026 search data.

Abstract

Content teams often need a short list of pages to check when click-through rate (ctr) looks low. Low ctr is not always a problem though: pages deep in Google usually get fewer clicks than pages near the top. So we ask a narrower question: which pages get shown enough times, but still click worse than other pages in the same position_tier?

We use the FlyRank ML Internship warehouse, focusing on March 2026 (month=2026-03). After aggregating daily rows to one row per page, we have 101,441 pages. 61,924 of them have at least 500 impressions that month (imp_mar >= 500). On a client holdout, a hand rule based on ctr_gap gets perfect Precision@50 because it is built from the same pieces as the label. A logistic model gets Precision@50 = 0.84 (base rate 0.464 on the same eligible test pages) and tends to put high-impression pages with non-zero ctr_mar nearer the top. The result is a ranked review list. It is not proof that editing a page will raise clicks, and it is not a model of Google's ranking system.

Introduction / Problem

Imagine an editor with hundreds of pages that get Google impressions. They cannot open every URL. They need a ranked list: start here first.

The hard part is that ctr alone is a bad sorting key. A page in position_tier = deep can have a low ctr for a normal reason: people see it lower on the results page. A page in top_3 with a weak ctr is more interesting. Also, if impressions are tiny, ctr jumps around by luck.

So the decision we support is: which pages should a reviewer check first because ctr_mar looks weak for that page's position_tier, while imp_mar is high enough to trust? A wrong pick wastes time (false alarm) or buries a page that was worth checking (miss).

Everything below is meant as decision support. We measured ranking quality on held-out clients. We did not run an experiment that proves a rewrite causes more clicks.

Data

This work uses the FlyRank ML Internship dataset, an anonymized search and content warehouse built for interns. Clients and pages are identified only with hash IDs such as client_hash_id and content_hash_id. There are no public client names or site URLs in the analysis we report here.

The full warehouse is large. The main daily table, fact_content_daily_performance, has about 79 million rows at the grain report_date × client × content, covering roughly January 2025 through June 2026. Related tables include dim_clients, dim_content, and a query-level table fact_content_query_90d. We did not use the query table for modeling, because its fixed 90-day window overlaps recent months and is easy to misuse.

For this project we worked on one mid-panel month partition: month=2026-03. That March slice alone has about 9.8 million daily rows. We rolled those days up to one row per page for March. After dropping pages with missing ctr_mar or pos_avg_mar, the modeling frame has 101,441 pages across the clients present in that slice. The "eligible" pool we use for the baseline and for Precision@K comparisons is pages with imp_mar >= 500: 61,924 pages.

What the main fields mean

  • imp_mar: total Google impressions for the page in March.
  • ctr_mar: clicks divided by impressions for March. In this dataset, rates are stored as percentage points, so 0.35 means 0.35%, not 35%.
  • pos_avg_mar: average Google position in March. 0 means "no position data," not a real rank, so those pages are dropped.
  • position_tier: a bucket built from average position (for example top_3, page_1, deep). This is how we compare like with like.
  • engagement_rate_mar: on-site engagement from GA4 when tracking exists. Many clients do not have usable GA4 in this month. When ga4_data_available is not true, zeros are not real "no engagement," so we treat that carefully.

Label

We define is_ctr_underperformer = 1 when a page's ctr_mar is below the median ctr_mar of its own position_tier, and imp_mar >= 500. That is a proxy for "worth a look," not a claim that the page is broken.

What we left out

  • client_hash_id / content_hash_id as model features (IDs only, used for joins and the client split)
  • trend_direction and trend_pct (those belong to a different refresh/decline lane, and they can leak a label)
  • raw query text and product flags
  • ctr_gap and tier median as model features (they are built from the label recipe)
  • the June sealed sample month as our development month (we used March instead)

Methodology

Assumptions

Expected ctr depends on position_tier. Below about 500 impressions, ctr_mar is noisy. Pages from the same client share site habits, so a random page split would look too easy. Features and the label both come from March, so this is a "what should we review now?" score, not a forecast of next month.

Features

The model uses five fields knowable at review time: imp_mar, ctr_mar, pos_avg_mar, engagement_rate_mar, and position_tier.

Baseline

The hand baseline ranks eligible pages by ctr_gap = tier_median_ctr - ctr_mar, and breaks ties with imp_mar. It is clear and fair to report. It also reuses the same ingredients as is_ctr_underperformer, so Precision@K looks perfect by design. In practice the top of that list fills with zero-click top_3 pages that all share a large ctr_gap.

Model

We fit logistic regression (random_state=42, max_iter=1000) and rank pages by the predicted probability of is_ctr_underperformer. ctr_gap is never fed to the model.

Validation and leakage check

We hold out about 25% of clients (11 test clients, 33 train clients). All pages from a held-out client stay in test. Model and baseline are compared on the same eligible test pages with imp_mar >= 500. As a leakage check, if we illegally add ctr_gap as a feature, ROC AUC jumps to 1.0. With the honest five features, AUC stays around 0.92.

Results

Numbers below use the same client holdout and the same eligible test pool (imp_mar >= 500). That pool has 17,110 test pages. The base rate of is_ctr_underperformer there is 46.4%. Precision@K asks: of the top K pages in the ranked list, what share truly have the label = 1?

Ranking P@10 P@20 P@50
Base rate (eligible) 0.464 0.464 0.464
Baseline ctr_gap rule 1.00 1.00 1.00
Logistic regression 0.70 0.80 0.84

On that second point, the two lists disagree a lot. On the held-out clients, the baseline top 10 and the model top 10 shared 0 of 10 pages. The model more often lifted pages with large imp_mar and non-zero ctr_mar, while the rule packed the top with zero-click top_3 ties. So the model is not "better Precision@K." It is a different ordering that puts more review stake near the top.

A random page split (shown only as a sensitivity check) looked weaker (Precision@50 = 0.74). The number we publish for skill is the client-holdout result.

Limitations

  • This is observational. We did not A/B test title or meta changes.
  • is_ctr_underperformer is only a proxy. A page can sit below its tier median for many reasons, including a zero-click search result or missing tracking.
  • Features and label both come from March 2026. This is not a past-to-future forecast.
  • GA4 coverage is sparse. engagement_rate_mar is missing or unreliable for many clients.
  • Perfect baseline Precision@K does not mean the baseline is the best review queue for people.
  • We are not reverse-engineering Google.

Ranked recommendations

For day-to-day use, score the current month with the logistic model, then sort by a simple page type (archetype) and by model score. Before spending time on a page, check that imp_mar >= 500, compare ctr_mar to the median of that page's own position_tier, and make sure tracking looks sane.

Across all 101,441 March pages, the archetype mix looks like this:

Archetype Share of pages Suggested next step
high_volume_ctr_gap ~15% Review title and meta first
zero_click_visible ~7% Check tracking / zero-click SERP issues first
deep_tier ~11% This is mostly a ranking problem, not a CTR rewrite
thin_volume ~39% Monitor only; ctr_mar is too noisy
healthy ~28% No action from this score

Confidence is moderate for ranking review attention on this March slice. Confidence is low for promising any client a click lift.
